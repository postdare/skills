# Slow-Think 设计原理

本文件解释 slow-think 的设计选择，仅在解释或维护 skill 时读取。运行审查不依赖这里的内容。

## 生成者与审查者分离

生成过程会形成锚定和自我合理化。独立审查者只接收原始需求和最终产物，可以在较少先入判断的条件下重新检查正确性。

隔离上下文不是让模型变得更聪明，而是改变它执行任务的角色、输入和完成标准，使审查过程更稳定。

## 偏差与对抗动作

| 常见失效 | 对抗动作 |
|---|---|
| 流畅表达掩盖错误 | 要求证据、反例和触发条件 |
| 锚定第一版方案 | 至少比较一个实质不同的替代方案 |
| 忽略隐含假设 | 列出关键假设并标注验证状态 |
| 只检查顺利路径 | 检查边界、异常、失败和重复执行 |
| 依赖“看起来正确” | 区分已验证事实和合理推断 |
| 产物答非所问 | 独立复述需求并判断是否匹配 |

## 使用成本

独立审查需要额外上下文和一次模型执行，适合高风险、长推理链或正确性证据不足的产物。低风险、无歧义的机械任务通常不需要这层复核。
